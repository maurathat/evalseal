What is built: six questions, four answered

Each question is separate, and answering one is not answering the next. Two of the six are not built, which is stated here rather than blurred.

layerthe question it answersstatus
configuration identitywhat is this configuration? BUILT
configuration classis this configuration an admissible member? BUILT
evidence envelopewere the material conditions preserved? BUILT
trace bindingwhat request was sent, what response came back? BUILT
attestationwere those conditions actually true? NOT BUILT
executionis this what actually ran? NOT BUILT

Conditions are declared, not attested. A run presenting tool_egress: none is making a claim, exactly as an operator presenting a prompt file is making one. The envelope establishes that presented conditions match the evaluated ones; it does not establish that either description was true. Asked who proves the condition actually held: nobody, in this prototype — a sandbox or an enclave would have to supply that. The model is the workload, never the trust source: it never decides membership, materiality, or whether its own evidence still holds.

But a declaration has three states, not two, and the third is inadmissible. It can be consistent but unattested; unobserved; or contradicted by evidence the issuer already holds. An evaluation performed by HTTPS calls to a hosted model may not declare that the network was unavailable — that is not an unattested condition, it is a false one. Issuance now refuses it (refuse_contradicted, ten regression tests, one of which reads the adapter's own source). This creates no attestation; it only stops the system signing what its own execution path has already disproved.

Identity establishes the subject of the evidence. The class establishes where the evidence may transfer. The envelope establishes under what conditions. Content addressing is how identity is implemented, not what the project is about. EvalSeal stops exactly where its evidence stops: attestation would establish whether the declared conditions were true, execution binding whether the identified system actually participated. Neither is built, and neither is claimed.

LICENSED DECLARED Integrity of the signed declaration. The presented declaration matches what the signing key signed.
LICENSED PRESENTED Identity of the presented artifacts. These are the same tool definitions, prompt and corpus documents.
LICENSED EVALUATED An evaluation cleared this configuration, under a named equivalence relation.
WITHHELD EXECUTED Not licensed. Nor the effective model, nor the approver’s authority unless the verifier anchored the key.

The boundary is machine-checked, not a disclaimer: benchmark row 7 attempts to read a passing verification as proof of execution and the system returns insufficient evidence. An unanchored signature verifies as VERIFIED (signer not anchored) — integrity without authorship.

What this does not do

Every one of these is a real gap, stated here so a judge does not have to find it. Two of them are the honest next quarter of work.

No enforcement point

EvalSeal is a CLI that computes identities and verifies receipts. Nothing in a live deployment is obliged to call it. The gate is real; the hook into a runtime is not built.

Level 2 is lexical, not semantic

Contamination detection at level 3 is character n-gram similarity. It finds paraphrase shaped like the original, not paraphrase that means the same thing.

Corpus overlap, not training exposure

All three detectors compare an eval set to a candidate corpus. Whether a model saw an item during training is a different question and is not answered here.

Materiality policy is declared, applied narrowly

The per-field policy is addressed and signed, and it governs the bake-off. Manifest receipts still record v0-implicit: the policy is not yet applied when the manifest is built.

Model binding stops at the declaration

The whole model object is bound — id, adapter, quantization, any prompt override — so a swap is caught. What weights actually served a request is outside what a declaration can prove.

One frozen external corpus

The reuse ladder is two filing transitions over pinned EDGAR accessions, and the MCP sample is a convenience sample of servers startable without credentials.
